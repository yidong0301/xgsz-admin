## 发布单详情「几秒闪一下」修复

- 现象：打开发布单详情，每隔约 4 秒整块闪动一次
- 原因：
  1. 详情在「发布中 / 待部署 / progressing 未就绪」时每 4 秒轮询，每轮都把整个弹窗 `innerHTML` 重建 → 滚动条、日志框一起重建，看起来就是"闪一下"
  2. 轮询没有上限，「重启」动作又把 `health_status` 置成 `DEPLOYING` 且从不复位 → 即使已经稳定也一直轮询（无限闪）
  3. 每次轮询还会重拉 Pod 日志，日志框先变"加载中…"再出现内容，二次闪
- 修复（前端 `app.html`）：
  - 每轮先算好 HTML，**与上一轮完全一致就不碰 DOM**；一致时只重新排下一轮
  - 真正变化时才替换，替换前后保留弹窗滚动位置；已加载的日志文本/滚动位置写入内存并在重绘后恢复，不再先清空再加载
  - 轮询只在「发布中 / 部署中 / progressing 且未就绪」时进行，且**最多 20 次（约 80 秒）**自动停
  - 重新打开详情（非轮询）时重置这些缓存
- 修复（后端 `k8s_release.restart` + `ReleaseOrderActionView`）：
  - 重启后**等待滚动完成**（最多 60 秒）再返回，按结果写入 `HEALTHY / UNHEALTHY`，不再把 `DEPLOYING` 永久挂在单上
- 验证：
  - 对 RELEASED 单执行重启：2.2 秒返回 `healthy=True, 2/2 就绪`，单车 `health_status=HEALTHY`
  - 打开详情后等 9 秒：`REL_DETAIL_TIMER=null`、轮询次数 0、弹窗 HTML 长度不变（无重绘即无闪动）
  - 前端 `node --check` 通过；后端 75 用例全绿
- 部署：镜像 `xgsz/admin-backend:20261111_p39`，`.env.p39.bak`；前端同步更新

## P3-6 指标面板（告警与自检）：metrics-server + 趋势曲线 + 阈值告警

按"告警与自检 = 看监控指标、收报警"补齐最后一块：真实指标面板。

### 1. metrics-server 安装（kind 无外网的处理）

- 集群节点拉不到外网镜像（docker.io 被墙、registry.k8s.io 实际也拉不下来），做法：
  1. 在 **VM 宿主机**用阿里云镜像源拉：`docker pull registry.cn-hangzhou.aliyuncs.com/google_containers/metrics-server:v0.7.2`
  2. 改 tag 成 `registry.k8s.io/metrics-server/metrics-server:v0.7.2`
  3. `kind load docker-image ... --name xgsz` 灌进节点
  4. `kubectl apply -f metrics-server.yaml`（在 args 里加 `--kubelet-insecure-tls`，kind 自签证书必须）
- 结果：`kubectl top nodes` 正常（xgsz-control-plane 5% / 4%）

### 2. 后端

## 任务卡在「已提交」的真实原因 + 15 秒内快速判失败（2026-11-11 下午）

- 反馈：「为什么我这个会测试这么久？我的测试命令很简单啊」（截图：任务 #43「测试」，
  `registry.k8s.io/kube-proxy:v1.29.2`，服务形态，状态「已提交 · 运行 6 分 11 秒」）

### 根因（不是命令的问题，是镜像没有启动命令）

- `kubectl describe pod infer-task-43-…`：`State: Waiting / Reason: CreateContainerError`，
  事件：`failed to apply OCI options: no command specified`
- `registry.k8s.io/kube-proxy:v1.29.2` **没有 CMD / ENTRYPOINT**，任务又没填「命令」→ 容器 spec 里没有任何启动命令 →
  容器根本创建不起来（Pod 一直 Pending，一次都没跑）
- 「在线服务」形态只看 Deployment 的 `available_replicas`，容器起不来就永远 0 → 一直显示「已提交」，
  只能等 K8s 的 600 秒 `ProgressDeadlineExceeded` 才变失败 → 用户看到的就是「跑了好久」

### 修复

1. 后端 `apps/k8s/services.py`：新增 `pod_failure_reason()`，同步时直接读 Pod 状态，**一个同步周期（≤15 s）内**判失败并写 `failure_reason`
   - `CreateContainerError / CreateContainerConfigError` → 立即失败（如 no command specified）
   - `ImagePullBackOff / ErrImagePull`、`Unschedulable` → 给 60 秒重试窗口再判（避免误杀）
   - `CrashLoopBackOff` → 重启 ≥2 次才判；非 0 退出码同理
   - 接入 `sync_status()` 的 SERVICE 分支（原来只有 `ProgressDeadlineExceeded` 一条路）
2. `apps/k8s/views/inference.py`：任务日志接口遇到「容器还没启动」时不再抛 K8s 原始异常，
   改为「容器还没启动，暂时没有日志 + 失败原因 + 排障建议（看事件 / 修正镜像或命令后重跑）」
3. 告警详情中文化（`apps/account/views/alerts.py`、`apps/ops/views.py`）：
   `no command specified` →「镜像没有默认启动命令，且任务未填写命令（请填「命令」或换带 CMD 的镜像）」，
   另补 ImagePull / CrashLoop / CreateContainer 的归类
4. 前端提交表单提示：命令留空 = 用镜像自带 CMD；只想跑简单命令请选「批任务（Job）」+ `["sh","-c","echo hi"]`
