# 真实推理任务（替换演示用的假推理）

> 版本：v1.0 ｜ 更新：2026-11-11

## 一、为什么要做

告警中心里的「推理任务失败：图像分类-030 / 风格迁移-028 / 人脸识别-026 / 推荐排序-025 …」都是
`scripts/seed_more.py`、`data/demo_data.json` 等演示脚本直接写库造出来的假数据：

- 镜像写的是 `registry.local/pytorch:latest`、`registry.local/asr:latest` 这种根本不存在的地址；
- 状态直接写死成 `FAILED`，`error_msg` 也是空/编的；
- K8s 里从来没有真正跑过（集群里查不到对应 Job/Pod）。

结果就是告警中心被一堆「推理任务失败」刷屏，但点进去既没有 Pod、也没有日志，说不清是真故障还是假数据。

现在改为：**推理任务必须是真下发、真运行、真出结果**。假任务已从库里和演示数据中清掉。

## 二、真实推理镜像

目录：`k8s/infer-demo/`

| 文件 | 作用 |
|---|---|
| `Dockerfile` | 基于 python:3.8-slim 系镜像，装 numpy / scikit-learn，**构建期训练**真实模型 |
| `train.py` | 在真实数据集上训练并落盘模型：UCI 手写数字（`load_digits`，1797 张 8×8 灰度图）、Fisher Iris（150 条 4 特征 3 分类） |
| `infer.py` | 运行时：`--mode batch` 批量真实推理（逐条预测/置信度/准确率/延迟）；`--mode serve` 在线推理（`/healthz` `/info` `/predict` `/metrics`） |

模型是构建期训练出来的 **sklearn MLP**，权重随镜像发布（`/models/*.joblib` + 训练报告 `*.json`），
容器里没有任何假数据、也没有写死的预测结果。

构建与灌入 kind（本机集群无外网，必须 load 进节点）：

```bash
cd k8s/infer-demo
docker build -t xgsz/infer-demo:1.1 .
docker save xgsz/infer-demo:1.1 -o infer-demo.tar
docker cp infer-demo.tar xgsz-k8s-control-plane:/root/infer-demo.tar
docker exec xgsz-k8s-control-plane ctr -n k8s.io images import /root/infer-demo.tar
```

> 有镜像仓库的环境：把镜像推到 Harbor/ACR/GHCR 后把 `XGSZ_INFER_IMAGE` 指过去即可，
> 也可以把 Dockerfile 的 `FROM` 换成 `python:3.8-slim`。

## 六、和告警中心的关系

告警中心（`GET /api/account/v1/alerts`）里的任务类告警只来自数据库里真实的
`InferenceTask`（`FAILED` / `SUBMIT_ERROR`），再叠加 K8s 的真实原因做中文归类：

| 真实原因 | 告警详情 |
|---|---|
| 镜像拉取失败 / 422 | K8s 拒绝了任务配置（请检查镜像地址 / 任务名称） |
| kubeconfig 不可用 | K8s 集群连接异常（请检查 kubeconfig） |
| 其它 | 原样截断展示真实错误信息 |

所以现在没有真实失败就不会再出现「推理任务失败」；如果需要演示真实故障告警，
直接提一个镜像写错的任务（例如 `nginx:not-exist`），告警中心会出现带真实 K8s 原因的任务告警，
点进任务详情还能看到 Pod 事件和日志——这条链路现在是真的。

## 七、任务命名、耗时与告警处置（2026-11-11 补）

### 1. 改名

任务名可以改（只改平台显示名，K8s 资源名 `infer-task-39-job` 这类保持不变）：

- 接口：`POST /api/k8s/v1/inference/task/<id>/rename`，body `{"name": "..."}`，写审计 + 运维日志
- 入口：推理任务 → 详情 → 「✎ 改个名字」
- 当前三个真实任务的名字：
  - 手写数字识别-批量推理（UCI digits 8×8）
  - 鸢尾花分类-批量推理（Fisher Iris）
  - 手写数字识别-在线推理服务（NodePort）

### 2. 耗时（跑多久）

`InferenceTask` 新增 `started_at` / `finished_at`（迁移 `k8s.0005`），同步时取 K8s 时间：

| 形态 | started_at | finished_at | 列表显示 |
|---|---|---|---|
| BATCH | Job `status.startTime` | Job `status.completionTime` | 耗时 4 秒 / 7 秒 |
| SERVICE | Deployment 创建时间 | 失败判定时间 | 运行 16 分 22 秒（已运行多久） |

实测（本机 kind）：

- 容器内**纯推理**：360 张手写数字 0.15 s（单条均值 0.408 ms），30 条鸢尾花 0.01 s
- **任务整体耗时**（Job 开始 → 结束，含调度 + 容器启动）：4 秒 / 7 秒
- **提交到界面显示「已成功」**：约 5–15 秒，取决于 15 秒一次的状态同步周期（celery `sync_inference_tasks`）
- **在线服务就绪**：约 10–20 秒（拉容器 + 探针 initialDelay 30s 不影响就绪判定）
- 注意：`registry.k8s.io/kube-proxy` 这类组件镜像不是推理服务，提交后会一直「已提交」直到 600 秒发布进度超时，
  不是平台卡住

### 3. 停机告警（P2）处置

演示数据里 5 台服务器写死 `Stopped`，导致告警中心一直报「服务器已停机」。处置（真实落库 + 留痕）：

| 机器 | 处置 | 结果 |
|---|---|---|
| old-server-01（CentOS 6.10） | 已退役 | `status=Retired`（新增状态），移出告警口径 |
| node-007 / 014 / 021 / 028 | 巡检确认恢复 | `status=Running` |

- `Server.status` 新增 `Retired`（已退役），迁移 `cmdb.0006`；告警/巡检只看 `Stopped`
- 每次处置写 `AuditLog`（update 服务器 …）与 `OpsLog`（asset），可在审计日志/运维日志里查
- `data/demo_data.json` 与 `scripts/seed_more.py`、`seed_demo.py` 同步修正，重新导数据不会再产生假停机告警
- 结果：告警中心 5 条 P2 → **0 条**（页面显示「✅ 暂无告警，系统运行正常」）

## 八、任务一直显示「已提交」怎么办（2026-11-11 补）

现象：提了一个「在线服务」任务，状态一直停在「已提交」，耗时几分钟甚至十几分钟。

真实原因（实测案例：镜像 `registry.k8s.io/kube-proxy:v1.29.2`、命令留空）：

```
pod/infer-task-43-xxx   0/1   CreateContainerError
kubelet: Error: failed to generate container "...": failed to apply OCI options: no command specified
```

- 该镜像**没有 CMD / ENTRYPOINT**，任务又没填「命令」→ 容器 spec 没有启动命令 → 容器起不来
- 「在线服务」形态按 **Deployment 副本就绪** 判断状态，容器起不来就永远没有可用副本 → 一直「已提交」
- 修复前只能等 K8s 的 600 秒发布进度超时（`ProgressDeadlineExceeded`）才会变失败，所以看起来「跑很久」

已修复（`apps/k8s/services.py: pod_failure_reason`）：同步时直接读 Pod 的真实状态，**一个同步周期（≤15 秒）内**就判失败并写 `failure_reason`：

| Pod 状态 | 任务提示 |
|---|---|
| `CreateContainerError` / `CreateContainerConfigError` | 容器创建失败（如 no command specified：镜像无 CMD 且没填命令） |
| `ImagePullBackOff` / `ErrImagePull`（超过 60 秒） | 镜像拉取失败（地址 / 拉取密钥） |
| `CrashLoopBackOff`（重启 ≥2 次） | 容器反复退出（看日志与事件） |
| `Unschedulable`（超过 60 秒） | 调度失败（资源不足 / 节点选择器无匹配） |

配套改动：

- 任务详情：日志面板不再抛 K8s 原始异常，改为「容器还没启动，暂时没有日志 + 失败原因 + 排障建议」
- 告警中心：失败详情中文化（`no command specified` → 「镜像没有默认启动命令，且任务未填写命令（请填「命令」或换带 CMD 的镜像）」）
- 提交表单提示：命令留空 = 用镜像自带 CMD；跑简单命令请选「批任务（Job）」+ `["sh","-c","echo hi"]`

正确的“简单测试”写法：

| 想验证什么 | 形态 | 镜像 | 命令 |
|---|---|---|---|
| 只想跑一条命令 | 批任务（Job） | `nginx:alpine` | `["sh","-c","echo hello"]` → 几秒完成 |
| 真实在线推理 | 在线服务 | `xgsz/infer-demo:1.1` | 留空（镜像自带 `python /infer/infer.py --mode serve`），端口 8080、探针 `/healthz` |
| 自己的在线模型 | 在线服务 | 自己的镜像 | 镜像必须常驻 HTTP 服务；CMD 里带启动命令 |

> 注：`registry.k8s.io/kube-proxy` 是 K8s 系统组件镜像（需要 `--kubeconfig`、privileged、hostNetwork 等），不能当推理服务用。
