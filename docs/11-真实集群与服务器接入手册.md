# 真实集群 / 服务器 / K8s 接入手册（上线操作手册）

> 面向：把演示环境（kind 单机）换成**真实服务器 + 真实 K8s 集群**时的操作步骤。
> 前置阅读：`docs/08-多集群接入清单.md`（集群侧细节）、`docs/09-Ubuntu-Docker部署.md`（平台部署）。
> 一键自检：`docker compose exec backend python manage.py check_access`

---

## 0. 先搞清楚「接什么」

平台只有**两条真正的连接**，第三条靠你自己保证：

```
① 用户浏览器 ──HTTP(S)/域名──▶ ② 平台（nginx 8080 → backend 容器）
                                    │
                                    ├─ kubeconfig（kube/clusters/<集群名>.yaml）──▶ ③ 各 K8s 集群 API:6443
                                    └─ 镜像仓库（Harbor/ACR/离线导入）—— 集群自己去拉，平台不代理
```

| 目标 | 平台怎么连 | 需要你提供 |
|---|---|---|
| **K8s 集群** | 一个集群一个 kubeconfig 文件，`backend` 容器按集群名加载 | kubeconfig（内含 API 地址 + 账号 token/证书）、网络可达 |
| **服务器（物理机/虚机）** | **目前只登记台账**（CMDB），不会 SSH 登录 | IP/配置信息；如需远程执行要另做 SSH 通道（见 §5） |
| **镜像仓库** | 平台不连，是**集群**去拉镜像 | Harbor/ACR 地址与凭据，或提前 `ctr images import` |
| **平台自身** | nginx + docker compose | 域名/证书/防火墙（见 §2） |

> 一句话：**集群"接入"= 放一个 kubeconfig；服务器"接入"= 登记资产（+ 可选 SSH 通道）；"能访问出来" = 三段网络 + 一次自检。**

## 1. 准备清单（动手前先确认）

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 平台部署位置 | 一台能长期跑的服务器（建议 4C8G 起），Docker + Compose | `docker compose ps` 全 Up |
| 平台 → 集群网络 | 平台所在机器能访问每个集群的 `6443`（或自定义端口） | `nc -zv 10.0.1.11 6443` |
| 集群 → 镜像仓库 | 各集群节点能拉镜像，或提前导入镜像 | `kubectl describe pod` 看 ImagePullBackOff |
| 集群账号 | 每集群一个专用 ServiceAccount（不要用 `admin.conf`） | `kubectl auth can-i create deployment -n xgsz-test --as=system:serviceaccount:kube-system:xgsz-deployer` |
| 命名空间 | 按环境预建：`xgsz-dev` / `xgsz-test` / `xgsz-prod` | `kubectl get ns` |
| 端口放行 | 平台侧 80/443（对外）、集群侧 6443（对内） | 安全组/防火墙 |

## 2. 第一步：让平台能被访问（对外）

1. 平台起来：`docker compose up -d`，`docker compose ps` 全部 `Up`；
2. 本机验证：`curl -I http://127.0.0.1:8080` → `200`；
3. 局域网验证：同网段另一台机器打开 `http://<平台IP>:8080`；
4. 域名 + HTTPS：按 `docs/07-域名与HTTPS部署.md` 配 nginx 反代 + 证书；
5. 只对外暴露 8080/443；MySQL(3307)/Redis(6380)/Mongo(27017) 在 compose 里已绑定 `127.0.0.1`，别改成 `0.0.0.0`。

> 端到端自检：登录平台 → 右上角「告警与自检」→ 五个组件全绿 + 「实时指标」有数据。

## 3. 第二步：接入第一台真实 K8s（最关键，做通一台再批量）

### 3.1 在目标集群建专用账号

```bash
# 1) ServiceAccount + 权限（最小可用：edit 够发布/查 Pod/看日志）
kubectl -n kube-system create serviceaccount xgsz-deployer
kubectl create clusterrolebinding xgsz-deployer \
  --clusterrole=edit --serviceaccount=kube-system:xgsz-deployer

# 2) 取 token
#    K8s ≥ 1.24（推荐，注意有效期，到期要换）
TOKEN=$(kubectl -n kube-system create token xgsz-deployer --duration=8760h)
#    K8s ≤ 1.23（老版本用 secret）
#    TOKEN=$(kubectl -n kube-system get secret \
#      $(kubectl -n kube-system get sa xgsz-deployer -o jsonpath='{.secrets[0].name}') \
#      -o jsonpath='{.data.token}' | base64 -d)
```

> 要更严的权限就自定义 ClusterRole（deployments/pods/pods/log/jobs/replicasets 的 get/list/watch/create/patch），
> 不要直接给 `cluster-admin`。

### 3.2 生成 kubeconfig（注意 server 地址！）

```yaml
# prod-01.yaml —— 文件名 = 平台里的「集群名」
apiVersion: v1
kind: Config
clusters:
- name: prod-01
  cluster:
    server: https://10.0.1.11:6443      # ← 必须是平台容器能访问到的地址，不能写 127.0.0.1
    insecure-skip-tls-verify: true       # 内网自签证书；有正规证书就删掉这行并配 certificate-authority-data
contexts:
- name: prod-01
  context: {cluster: prod-01, user: xgsz-deployer, namespace: default}
current-context: prod-01
users:
- name: xgsz-deployer
  user: {token: "<把上面的 TOKEN 填这里>"}
```

- 取值：`kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}'` 看真实 API 地址；
- **kind 环境**例外：`server` 必须写容器网络别名 `https://xgsz-k8s-control-plane:6443`（写 127.0.0.1 一定连不上）。
- 证书 SAN 不含该 IP 时：要么重新签证书，要么内网 `insecure-skip-tls-verify: true`。

### 3.3 放到平台并生效

```bash
mkdir -p kube/clusters
cp prod-01.yaml kube/clusters/prod-01.yaml

# kubeconfig 是只读挂载，改了要重建/重启后端（客户端有缓存）
docker compose restart backend celery-worker celery-beat
```

### 3.4 验证（三层，从粗到细）

```bash
# ① 平台自带的自检命令（推荐，一次跑完 组件/集群/权限/指标/镜像仓库）
docker compose exec backend python manage.py check_access --namespace xgsz-test

# ② 只看这一台
docker compose exec backend python manage.py check_access --cluster prod-01

# ③ 平台界面
#    环境管理 → K8s 集群接入状态 → 刷新 → 应看到「在线 / 节点数 / 版本」
```

### 3.5 走一次真实发布验证

1. 「发布单 → 新建」：目标集群填 `prod-01`，命名空间 `xgsz-test`，镜像用内网仓库里真实存在的镜像；
2. 审批 → 执行发布 → 详情页确认 Pod `Running`、健康检查 `健康`；
3. 点 Pod 行「日志」能看到容器日志；
4. 执行「回滚」，确认镜像回到上一版本；
5. 「推理任务」提交一个 BATCH 任务，确认能创建 Job 并读到日志。

> 这一套跑通 = 这台集群就真正接好了。

## 4. 第三步：批量接入 8 台

对每台集群重复 §3.1–3.3（文件名 = 集群名 = 发布单里填的名字），然后：

```bash
ls kube/clusters/            # 期望 8 个 yaml（+ kind.yaml 可保留作演示）
docker compose exec backend python manage.py check_access --namespace xgsz-prod
```

期望输出：`已配置 8 台 / 目标 8 台`、每台 `在线 + 权限 OK + 指标 OK`。

**命名与环境规划建议：**

| 环境 | 集群 | 命名空间 | 说明 |
|---|---|---|---|
| dev | cluster-dev | xgsz-dev | 研发自测 |
| test | cluster-test-01 / 02 | xgsz-test | 联调、验收 |
| prod | cluster-prod-01 ~ 05 | xgsz-prod | 生产，`prod` 命名空间**要求预先创建**（平台不会自动建） |

CMDB 台账同步登记（资产管理 → K8s 集群）：名称、API Server、版本、节点数、环境、负责人 —— 只用于展示与「一键登记」匹配，不参与连接。

## 5. 第四步：服务器（物理机/虚机）怎么接

**现状（要清楚）：**

| 能力 | 现状 |
|---|---|
| 资产管理 → 服务器 | ✅ CMDB 台账（IP/CPU/内存/系统/负责人），可手工登记、Excel/CSV 导入 |
| 阿里云 ECS 自动同步 | ✅ 填 AccessKey 后定时同步（`任务编排/定时任务` 里 `sync_ecs`） |
| 机器节点 / 节点详情 | ✅ 但走的是 **K8s Node API**（cordon/drain/标签/污点/事件） |
| SSH 登录服务器执行命令 | ❌ **未实现**（代码里没有接线，只有打包的 ansible 依赖） |

所以「服务器接入」目前 = **登记 + 云同步**。要让平台真的"连上服务器"，三个方案选一：

| 方案 | 做法 | 适合 |
|---|---|---|
| **A. SSH 通道**（推荐起步） | 资产加 `ssh_port/ssh_user/凭据`（`utils/prpcrypt` 加密存）；后端用 paramiko 执行**白名单只读命令**（uptime/df/free/ps）+ 采集主机指标 + 全量审计 | 几十台以内，想快速看到"远程执行" |
| **B. Agent 上报** | 每台装 node_exporter/自研 agent，主动推到平台；平台只收不发 | 上百台、跨网段、不想存密码 |
| **C. 堡垒机中转** | 平台经跳板机 SSH，凭据统一在堡垒机 | 有等保/审计要求 |

> 需要的话我可以按 A 方案落地：凭据加密 + 只读命令白名单 + 审计日志 + 「远程执行」按钮。

## 6. 第五步：镜像仓库（最容易卡住的一步）

集群拉不到镜像 = 发布单一直 `ImagePullBackOff`。二选一：

**① 内网 Harbor（推荐）**
```bash
# 每台集群节点上（或用 DaemonSet / 批处理）
docker login harbor.corp.local -u robot -p '***'
# 或写 imagePullSecret：平台发布单里填「镜像拉取密钥」名字
kubectl create secret docker-registry harbor-cred -n xgsz-test \
  --docker-server=harbor.corp.local --docker-username=robot --docker-password='***'
```

**② 离线导入（无外网）**
```bash
# 平台侧把镜像包灌进每台集群节点
docker save app:v1.2.3 -o app.tar
docker cp app.tar <node-container>:/root/app.tar
docker exec <node-container> ctr -n k8s.io images import /root/app.tar
```

验证：`manage.py check_access --registry harbor.corp.local:443`（显式指定的仓库不可达会算 FAIL）。

## 8. 常见失败 → 原因 → 处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 集群「不可达：timed out」 | 平台→6443 不通 / server 写了 127.0.0.1 / 防火墙 | 换成容器可达 IP，放行 6443，`nc -zv` 先测通 |
| 「certificate signed by unknown authority」 | kubeconfig 证书 SAN 不含该 IP | 重新签证书含 IP，或内网 `insecure-skip-tls-verify: true` |
| 「401 Unauthorized」 | token 过期（`create token` 有有效期） | 重新 `create token` 并更新 yaml，`restart backend` |
| 「403 Forbidden」 | ServiceAccount 没绑 ClusterRole | 补 `clusterrolebinding`，用 `check_access` 的「权限」项确认 |
| 「未找到目标集群 kubeconfig」 | 文件名与发布单里的集群名不一致 | 文件名必须完全相同（区分大小写，不要带 `.yaml` 在发布单里） |
| 改了 yaml 不生效 | 客户端有缓存 | `docker compose restart backend celery-worker celery-beat` |
| 指标页「metrics-server 不可用」 | 集群没装 metrics-server | 按 `k8s/metrics-server.yaml` 部署（kind 需 `--kubelet-insecure-tls`） |
| 发布卡 `ImagePullBackOff` | 集群拉不到镜像 | Harbor 账号/secret、网络、或离线导入 |
| 发布卡 `Pending` | 资源不足 / 没有可调度节点 | `kubectl describe pod`，看 CPU/内存/污点/亲和性 |

## 9. 回滚与备份

- **平台数据**：`docker compose exec mysql mysqldump ...` 每日备份；Mongo/Redis 非关键；
- **kubeconfig**：`kube/clusters/` 纳入备份，权限 `600`，只给运维账号；
- **平台版本回滚**：`docker compose` 镜像打 tag（沿用 `xgsz/admin-backend:日期_pXX` 习惯），保留上一版镜像；
- **集群侧回滚**：发布单自带「回滚」（恢复上一版镜像与副本数），异常时先用它。
