## 0. 先说结论

1. **不要再继续铺页面**。当前缺的不是菜单，而是三条真实链路：任务执行、节点管理、构建交付。
2. **第一优先：真实 K8s 任务闭环**（P3-1）。Job 代码已有，但存在 5 个阻断点：单集群、无后台状态同步、无 Service/访问入口、日志 1 小时后随 Job 删除、演示兜底不透明。
3. **第二优先：节点/机器管理**（P3-2）。后端已有 Node/Pod/Deployment/Namespace/Logs API，前端 0 调用；补 UI 比从零开发快，但必须先统一多集群客户端。
4. **CI/CD 必须重做执行层**（P3-4）。现在的「流水线」是在 backend 容器里 `subprocess(shell=True)` 跑命令，等于 RCE 面，不是生产可用的 CI/CD。
5. **先止血再谈功能**（P3-0）：遗留演示页内置明文管理员口令、诊断 Agent 接口未鉴权、密钥明文、3 个必崩接口，必须在接真机前处理。
6. **可用性不是最后补的**：每个阶段都带「权限 + 审计 + 配额 + 失败路径 + 验收脚本」，否则后期接真机会返工。

### 0.1 三条要求如何落到路线

| 你的要求 | 对应能力 | 主要阶段 |
|---|---|---|
| ① CMDB、CI/CD、DevOps、资产管理 | 资产台账/关系/变更、应用与流水线、构建与发布、运维入口 | P3-3、P3-4、P3-6 |
| ② 任务编排、持续交付、运维管理 | 模板/编排/调度、发布与环境晋级、节点/告警/巡检 | P3-1、P3-2、P3-4、P3-5 |
| ③ 登录跑推理、管理机器、后期接真机可用 | K8s 任务执行（Service/Job）、节点管理、接入清单、生产基线 | P3-0、P3-1、P3-2、P3-6 |

> 结论：三条要求不是三个独立系统，而是同一条链路的三段：**资产/集群 → 任务/构建 → 发布/运维**。路线按链路推进，避免做成三个互不相通的模块。

### 0.2 不建议做的事

- ❌ 继续加「看起来有、实际不跑」的页面（环境卡片、假图表、假日志）。
- ❌ 把 backend 容器里的 `subprocess` 包装成「流水线」——不可复现、无隔离、无法审计。
- ❌ 在数据库里存明文 SSH 密码/云 AK（`cmdb` 里有旧模型，接真机前必须收敛）。
- ❌ 等到接真机才补权限、审计、配额、失败路径。
- ❌ 再次大改导航：保留当前已验证的演示路径，新能力按分组补位。

## 5. 分阶段路线

### P3-0 止血与生产基线（1 周，P0，与 P3-1 并行）

> 审计结论：上线前最大的风险不是功能缺失，而是「明文口令、未鉴权入口、任意 shell、默认密钥、无备份」。先止血，再谈新功能。

**A. 安全止血（必须最先，1–3 天）**

| # | 问题 | 处理 | 验收 |
|---|---|---|---|
| 1 | `dashboard.html`、`inference.html` 内置明文 `admin/admin123456` 自动登录；`infer.html` 是本地演示页 | 删除前两个；`infer.html` 合并进 SPA 后删除；`dashGo('infer')` 改 `navTo('infer')` | 全站无明文口令文件；工作台入口进真实推理页 |
| 2 | `/api/application/v1/diagnosis/agent` 未鉴权即可 SSH 装 agent，且固定私钥不存在 | 下线该接口；如保留，加鉴权 + 参数校验 + 审计 | 匿名请求 401/403 |
| 3 | `CloudAK.access_secret`、`EcsAuthSSH.password` 明文入库；Ansible 在容器内执行 | 接真机前先**禁用/隐藏** Ansible/SSH 入口；后续用 Fernet/KMS 加密 + 单独 Runner | 数据库无明文密钥；前端无入口 |
| 4 | `PASSWORD_HASHERS` 首选 MD5；token 24h 不可吊销；记住密码 Base64 可逆 | 改 PBKDF2/Argon2；token 加版本号；记住密码改 opt-in 或移除 | 改角色/停用后旧 token 失效 |
| 5 | 3 个必崩点：`inference.py` 缺 `ApiException` 导入（配额永不创建）；`ansible_tasks.py` 缺 `status`；`asset.py` server 按 name 创建 500 | 各 1 行修复 + 回归 | 对应接口 200 |
| 6 | Pod/Deployment 删除、Pod 日志三处权限表达式恒 403 | 修正表达式，补角色矩阵测试 | 超管/主管/工程师行为符合预期 |
| 7 | 节点 drain/删除、Pod/Deployment/Namespace 变更、资产增删改、Ansible 执行无审计 | 统一审计中间件（user FK、request_id、object、cluster/ns、before/after） | 每个破坏性操作可追溯 |
| 8 | 前端列表只显示 10 条（后端 `page_size=10`，前端不传 page；人员 `limit=200` 参数名错误） | 统一分页组件，前端传 `page/pageSize` | 100 条可分页；总数与表格一致 |

**B. 交付基线（部署审计 9 项，摘要）**

| # | 缺口 | 处理 |
|---|---|---|
| 1 | `SECRET_KEY` 硬编码兜底、prod 未注入 | 生产强制读环境变量 |
| 2 | `ALLOWED_HOSTS=*`、`CORS_ORIGIN_ALLOW_ALL=True` | 白名单 + 关闭 CORS |
| 3 | 80 端口明文直连业务 | 只留 ACME + 301 |
| 4 | 默认口令/演示数据进生产 | 首登改密；演示仅演示机 |
| 5 | 备份用 tar 打运行中的库 | `mysqldump`/`mongodump` + 异地 + 恢复演练 |
| 6 | 证书续期手工 reload | certbot 常驻 + reload 钩子 + 到期监控 |
| 7 | `/health` 需 JWT、探针只看 TCP | 非鉴权 `/healthz` + HTTP 探针 |

## 7. 真实服务器 / K8s 接入清单

- **功能**：失败有明确原因；重复提交幂等；超时/取消；无演示数据冒充真实数据。

- **观测**：任务/发布状态、失败率、耗时；告警通知。
- **恢复**：数据库备份/恢复演练；kubeconfig/密钥可轮换。

## 9. 需要拍板的 9 件事

1. **GPU 硬件**：型号、数量、驱动、device plugin、整卡/MIG/共享；决定配额口径与镜像。
2. **集群来源**：8 台集群归属/网络/是否 k3s/控制面谁运维；K8s 版本基线统一。
3. **镜像仓库与交付方式**：Harbor / ACR / 离线导入；是否允许出网拉镜像；保留与扫描策略。
4. **Git 平台**：GitLab / Gitea / GitHub；webhook 网络是否通；构建在集群内还是独立 runner。
5. **域名与证书**：备案进度、LE 还是商业/内部 CA、cpolar 是否关停、续期责任人。
6. **安全边界**：是否允许用户提交任意镜像/命令；镜像白名单、Pod Security、命名空间隔离。
7. **可用性目标**：SLA 几个 9、RTO/RPO、是否接受单机 compose 首发、告警接收人与值班、验收签字人。
8. **推理形态**：在线服务（Deployment+Service）为主，还是离线批任务（Job）为主，还是两者都要？
9. **物理机管理方式**：只做 K8s 节点运维，还是也要 SSH/Ansible 管宿主机？后者需要独立的受控 Runner 与凭据加密。

> 没有第 7 项，后面的备份频率、监控粒度、是否上高可用都没有判断依据。
